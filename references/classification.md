# 分类引擎（七类 A–G）

本文件只在分类置信度为中/低、出现复合目标、或需要边界话术样例时载入。

## 七类定义与判定信号

| 类 | 名称 | 判定信号 | 典型话术 |
|---|---|---|---|
| A | 学科 | 宽泛体系，含多个分支，无具体交付物 | 学数学、入门经济学、系统学计算机科学 |
| B | 单个知识点 | 目标是单一概念、原理、机制 | 泰勒展开、傅里叶变换、电磁感应、Transformer |
| C | 技术域 | 名词是工具集合 / 工程领域，涉及架构与分层 | 嵌入式系统、机器人、计算机网络、区块链 |
| D | 软件工具 | 名词是可安装、可操作的具体软件或语言工具链 | Git、Docker、Linux、VS Code、MATLAB |
| E | 具体问题 | 疑问句式，问「为什么」或「怎么工作」 | 电容为什么能储能、神经网络如何学习 |
| F | 项目目标 | 含交付物、场景或「做出来」的动词 | 做智能车、开发 App、搭一个网站 |
| G | 能力素养 | 目标是「变得擅长某种活动」，无固定知识点 | 编程、算法设计、科技写作、数据分析、演讲 |

## 判定顺序（命中即停）

1. 有明确交付物或使用场景 → F
2. 「为什么 / 如何工作 / 怎么做到」问句 → E
3. 名词是具体可操作工具 → D
4. 名词是工具集合、工程领域、分层架构 → C
5. 名词是单一概念或机制 → B
6. 目标是宽泛体系 → A
7. 目标是「擅长 / 会做」某种活动 → G

信号冲突时优先问「用户要的是产物还是能力」：有产物走 F/E，要能力走 G，纯认知走 A/B/C/D。

## 复合分类

- 允许一主 + 最多两辅，必须标注主类与辅类。
- 常见组合：`嵌入式系统` = C 主 + A/F 辅；`Teach me Python` = D 主 + G 辅；`Transformer 架构` = B 主 + C 辅；`为做智能车学嵌入式` = F 主 + C 辅。
- 复合目标仍然只生成一套三图；辅类只影响分解链与练习类型，不另建图。
- 主类决定分解链与首轮产物；辅类决定补充视角（如 F 辅要求补测试与调试环节）。

## 边界样例（易误判）

| 输入 | 正确分类 | 易误判为 | 区分点 |
|---|---|---|---|
| 「讲讲梯度消失」 | B | E | 没有「为什么」问句，只是指定概念 |
| 「梯度消失为什么会发生」 | E | B | 有因果问句，需要因果链与验证 |
| 「学 Linux 内核」 | C | D | 涉及架构与机制，不是命令操作 |
| 「学 Linux 常用命令」 | D | C | 目标是可执行操作 |
| 「三天精通量子场论」 | A（时间冲突） | — | 分类不变，走失败处理的最小可达子集 |
| 「学点东西」 | 无法判定 | A | 目标指向不明，走 1 个澄清 + 降级 |

## 澄清规则

- 目标已足够清楚时不提问，直接给分类与三图概览。
- 仅在「无法从原话推断对象或意图，且任何默认假设都会显著改变图形态」时提 1 个问题。
- 提问必须与降级产物同时给出，不得只提问后停下等待。
- 提问格式：`假设你要学的是 X（通用入门），若不是，请说明具体方向。` 后接基于该假设的概览。

## 分类输出字段

```
主类：C 技术域 ｜ 辅类：A 学科、F 项目 ｜ 置信度：高
依据：原话「学嵌入式系统」= 工程领域名词；无交付物，故 F 为辅而非主
```

置信度：高（信号唯一）、中（两个信号相当）、低（含糊或多义）。低置信度时仍输出分类，并标「假设：…」。


## V2 增补：学习意图层与置信度

分类（A–G）与学习意图是**两个独立维度**，不得互相替代。canonical 枚举见 `core/data-schema.md` §5。

| 维度 | 取值 |
|---|---|
| 分类 | academic_subject / individual_concept / technical_domain / software_tool / specific_problem / practical_project / competency |
| 意图 | understand / use / research / build / solve / master / exam |

示例：「我想学 Python 来做 AI 助手」→ 主类 `software_tool`，辅类 `practical_project`，意图 `build`。

输出字段：`primary`, `secondary[]`, `intent`, `confidence`, `evidence`（原话关键词）。置信度取 unassessed / provisional / supported / strong；置信度低时给暂定分类 + 一句假设 + **1 个**澄清问题，不追问多余信息，也不因含糊而停止输出降级概览。

边界复核清单（由 Agent 执行，脚本只检查术语一致性）：混合类别、含糊请求、极短请求、多目标、工具 vs 能力、概念 vs 具体问题、技术域 vs 实践项目。
