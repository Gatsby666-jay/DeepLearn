# V2 质量门禁（五道门 + 六问验收）

每轮输出前自检。任一门未过，不得进入下一节点、不得标记掌握、不得宣称「拆解完成」。集中管理五个维度的验收标准，避免规则散落在各处被淡化。

## 核心判据：深度 ≠ 目录长度

增加层级、名词、分支数量都不等于拆得更深。真正的深度由「能否回答六问」决定：三个节点但六问齐全的拆解，优于三十个节点却只有一句定义的目录。

**禁止目录式拆解**：只列章节名、概念名、功能清单，没有机制、原理、依赖、验证的条目，一律不计入拆解成果。

## 六问原子验收门（Atomic Unit Gate）

每个被标为 L5 基础单元 / 原子知识单元的节点，必须逐条能回答：

| # | 问题 | 对应依据 | 不合格的表现 |
|---|---|---|---|
| 1 | 为什么这个知识存在？ | 动机（first-principles #2） | 只有定义，说不出由来 |
| 2 | 它解决了什么问题？ | 动机 + 应用 | 说不出「没有它会怎样」 |
| 3 | 它依赖什么基础知识？ | `prerequisites[]` | 前置为空且未声明为基础边界 |
| 4 | 它为什么能够成立？ | 第一性原理 #6 + 机制 #5 | 用「显然 / 一般来说 / 经验上」代替论证 |
| 5 | 能不能从基础原理推导出来？ | 推导 #7 / 反向教学 | 只能复述结论 |
| 6 | 如何证明自己真正理解了？ | 验证 #12 + 迁移任务 + 掌握度证据 | 只做对原题就宣称掌握 |

缺任一项 → 该节点**不是原子单元**，继续下钻或补齐，不得进入路线图。
六问用于内部校验，输出时按需精简，不机械打印六行答案。

## G1 拆解门 —— 拆到知识原子

- 每个 L3 以下节点必须带 `mechanism` 或 `principles[]`，否则视为目录条目。
- 原子节点过六问才算完成；层级数、节点数、字数都不作为深度指标。
- 显式声明基础边界及理由，不无限下钻、不生成无意义递归定义。
- 短概念不等于基础概念：公式越短，越要补齐它依赖的深层原理。

## G2 关联门 —— 建立依赖关系网络

- 依赖图**零孤立节点**：除显式声明的「基础边界」外，每个节点至少有一条入边或出边。
- 运行 `scripts/validate_map.py --strict`：存在孤立节点即失败，必须补边或标注理由。
- 按 three-graphs.md 的跨分支边发现清单主动找边，不让知识点彼此孤立。
- 依赖图无环；结构图不得表达「必须先于」。

## G3 原理门 —— 追溯第一性原理

- 每个重要节点写一条**原理追溯链**：`节点 → 机制 → 支撑原理 → 基础边界`，并明确回答「为什么成立」。
- 只给「定义 + 举例」不算解释；类比必须标注并说明失效之处。
- 可推导的结论必须给推导路径，或链接到反向教学任务。
- 区分已确立事实与简化模型，不跳过中间推理。

## G4 教学门 —— 真正循序渐进

- 一课只引入**一个新机制 / 新概念**；讲解正文 ≤25 行。
- 起始确认前置，结尾必有「请用户独立推理」的任务与完成判据。
- 收到作答后必须先给反馈，不得直接跳下一课。
- 不理解时按 teaching.md 回退前置或换表征，不重复同一段文字。
- 禁止用大段文字墙代替教学交互。

## G5 闭环门 —— 动态检测与调整

- 掌握度升级必须有练习、推理或实践证据；无证据不升级。
- 诊断出薄弱点后执行完整闭环：
  1. 定位**最早的失败节点**（不是所有答错的题）；
  2. 定向回补该节点及其必要前置；
  3. **换题重测**，不重复使用原题；
  4. 重排路线图：插入复习节点、后移受影响后继、必要时下调路径；
  5. 更新三图版本号与 state（证据摘要、薄弱点、下一推荐任务）；
  6. 给出新的「下一步」。
- 路线图是动态的：掌握度变化、薄弱点、新增前置、用户约束变化都会触发重排，不是一次生成后固定不变。

## 每轮自检清单

- [ ] 新增的每个原子节点过了六问
- [ ] 无目录式条目（L3 以下都有机制或原理）
- [ ] 依赖图零孤立、无环、含跨分支边，`--strict` 通过
- [ ] 重要节点有原理追溯链，能回答「为什么成立」
- [ ] 本课只有一个新机制、≤25 行、有独立推理任务与反馈
- [ ] 掌握度变更有证据，且已同步三图与 state
- [ ] 首轮仍 ≤40 行，没有一次性倾倒教学内容

## 门禁失败时的动作

| 失败 | 动作 |
|---|---|
| 六问缺项 | 继续下钻或补齐动机 / 依赖 / 推导 / 验证，不进路线图 |
| 出现孤立节点 | 补跨分支边，或显式声明为「基础边界」并给理由，重跑 `--strict` |
| 只有定义没有原理 | 补机制与第一性原理追溯链，不输出「已完成拆解」 |
| 一课塞了多个新概念 | 拆成多课，只保留当前一课 |
| 无证据却声称掌握 | 撤回掌握度变更，补一道最小验证题 |
| 诊断后未重排路线 | 执行 G5 六步闭环，不进入下一节点 |


## V2 增补：类别感知、质量分与闭环门

六问改为**类别感知**：每问 `passed` / `failed` / `not_applicable`，不适用给理由；不把无关问题强加给每个节点。

分解质量分：六维各 0–2、总 12；`dependency_correctness` / `explanatory_depth` / `verifiability` 任一 <2 即门禁失败，总分不替代关键维度。字段与阈值由 `scripts/validate_schema.py` 做确定性校验。

G4 的「≤25 行」是可读性指导而非硬上限；判据以「一课一个新机制 + 独立推理任务 + 反馈」为准。

G5 闭环门补齐：`REMEDIATE → REPLAN → PERSIST → CONTINUE` 必须回流到 `TEACH` / `MAP` / `PLAN`，不得线性结束；无 `PERSIST` 不得 `CONTINUE`；`VALIDATE` 失败不得进入 `PLAN`。闭环定义见 `core/orchestrator.md`。
