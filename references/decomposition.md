# 递归拆解引擎

展开分支、进入 Decompose / Deep Dive 模式时载入。

## 层级（概念性，非固定深度）

| 层 | 含义 | 典型产物 |
|---|---|---|
| L0 | 整体学习目标 | 一句话目标 + 完成标准 |
| L1 | 主要知识域 / 系统组件 | 3–6 个分支 |
| L2 | 模块 / 分支 | 每分支 3–7 项 |
| L3 | 单个概念或技术 | 可命名、可查证的知识点 |
| L4 | 子概念与机制 | 「它如何工作」的中间推理 |
| L5 | 基础知识单元 | 可独立教与测的原子单元 |
| L6 | 原理 / 定律 / 公理 / 元机制 | 基础边界，显式声明 |

层级是描述用的刻度，不是要求每个分支都必须走到 L6。只要继续下钻还能揭示有意义的前置或隐藏机制，就继续；否则停止并声明边界。

## 八问模板（对每个节点依次问）

1. 它**确切**是什么？给一句不含循环定义的表述。
2. 它由哪些**组件**构成？
3. 理解每个组件需要哪些**更小的概念**？
4. 每个更小概念又**依赖**什么？
5. 什么**机制**解释它如何工作？
6. 什么**原理**解释它为何成立？
7. 现在能否**独立解释并应用**它？
8. 要达到真正理解，还**缺**什么？

第 7 问为否 → 回到第 3–6 问继续下钻。第 8 问的答案若指向目标范围之外 → 记为基础边界候选，不继续拆。

## 七类专用分解链

| 类 | 链 |
|---|---|
| A 学科 | Subject → Branch → Chapter → Concept → Sub-concept → Foundation |
| B 知识点 | Concept → Motivation → Definition → Mechanism → Dependencies → Derivation → Applications |
| C 技术域 | Technology → Architecture → Layer → Component → Interface → Mechanism → Principle |
| D 工具 | Tool → Functional modules → Commands → Workflows → Internal mechanisms → Advanced usage |
| E 问题 | Question → Subquestions → Causal chain → Required knowledge → Fundamental explanation → Verification |
| F 项目 | Goal → Requirements → Architecture → Subsystems → Modules → Implementation → Testing |
| G 能力 | Target ability → Competency model → Subskills → Exercises → Performance criteria → Mastery |

链用于决定「下一层该找什么」，不用于决定学习顺序（顺序来自依赖图）。

## 各类补充项（不可省略）

| 类 | 补充要求 |
|---|---|
| A | 在结构图之外给出渐进课程表（curriculum）；阶段顺序仍取自依赖图拓扑序，不取教材章节顺序 |
| B | 必须列出至少 2 条常见误解及澄清；补历史或实践动机、与易混概念的对照 |
| C | 每个组件额外标注相关标准 / 协议 / 工具与接口契约；说明该组件存在的原因 |
| D | 从基础用法到进阶应用递进；每个关键操作给一个可观察输出作为完成判据 |
| E | 拆完因果链后必须回到原问题给出完整回答，不以「原理已解释」收尾 |
| F | 需求分「功能」与「非功能」两类；非功能至少覆盖适用的性能、可靠性、可调试性、成本约束 |
| G | 每个子技能配客观评价准则与刻意练习任务；练习必须可观察、可反馈 |

## 节点 schema

持久化或写入知识图时，每个节点包含：

| 字段 | 说明 |
|---|---|
| `id` | 稳定唯一标识，三图共用，建议 `L{层}-{序号}` |
| `name` | 概念名 |
| `description` | 一句不含循环定义的表述 |
| `parent` / `children` | 结构图的父子关系（父唯一） |
| `category` | A–G 分类标记 |
| `prerequisites[]` | 依赖图边（可多、可跨分支） |
| `difficulty` | 1–5 |
| `importance` | 必 / 选 / 拓 |
| `objectives` | 学完能做什么（可观察） |
| `principles[]` | 支撑它的底层原理 |
| `related[]` | 关联与易混概念 |
| `applications[]` | 实际应用 |
| `mastery` | 0–5，见 assessment.md |

## 原子知识单元判据（全部满足才停）

- 表达一个相对独立的思想或机制；
- 它的前置可识别；
- 解释它时不必隐藏重要中间推理；
- 可独立教学、可独立测试；
- 再拆会变得琐碎，或超出本次学习目标的可用范围。

**短概念 ≠ 基础概念**：一个只有一行的公式可能依赖极限、连续性、收敛性等多条深层原理。判断依据是依赖数量，不是表述长度。

示例（错误 → 正确）：
- 错误：把「学习率」当作原子单元，因为它只有一个名字。
- 正确：向下补齐「步长与更新方向」「损失曲面」「收敛条件」，再判断哪些属于本次目标的边界。

## 基础边界（避免无限拆解）

到达真实边界时，输出一句显式声明，格式：
`基础边界：<名称> —— 在<解释框架>下将其视为基础，理由：<…>；继续追问属于<另一领域>。`

不同框架有不同的底：

| 框架 | 可接受的基础 |
|---|---|
| 物理 | 实验确立的定律与模型 |
| 数学 | 公理、定义、逻辑推断规则 |
| 编程 / 计算 | 计算模型、逻辑、硬件机制 |
| 工程 | 物理约束与数学模型 |
| 经验性学科 | 可重复观测与统计证据 |

## 反无限拆解（显式禁止）

- 不生成无意义的递归定义（「A 是 A 的一种」）。
- 不无限追问基础术语（不再追问「什么是数字」「什么是集合」，除非目标本身就是该领域）。
- 不假定所有主题有唯一绝对底层；同一概念在不同解释框架下可以有不同的底。
- 不为凑层级人为增加中间层；层级数由内容决定。
- 不把「留待以后」当作拆解完成 —— 未展开的分支要明确标注「后续展开」及其触发条件。

## 拆解完成的检查点

- [ ] 每个叶子节点满足原子单元判据；
- [ ] 每个节点的 `prerequisites[]` 已填写或明确标注「无」；
- [ ] 已标出跨分支依赖；
- [ ] 已声明基础边界与理由；
- [ ] 节点总数在可维护范围（学科 ≤40、技术域 ≤30、项目 ≤25、知识点 ≤15），超出时合并或标注后续展开；
- [ ] 未出现循环定义或为凑数新增的节点。
