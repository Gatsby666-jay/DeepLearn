# 自适应教学引擎

Learn / Deep Dive 模式、以及任何「开始教我」请求时载入。

## 教学循环（九步）

1. **定位当前节点**：从路线图取当前节点，读出其 `prerequisites[]` 与 `mastery`。
2. **探明已有理解**：用 1–2 个短问题或一个小任务确认起点，不假定用户已懂前置。
3. **直觉先行**：给一个具体画面、现象或类比，让概念先有落点。
4. **形式化定义**：给严格表述，并说明与直觉的对应与差异。
5. **机制**：按因果或时间顺序逐步展开「它如何工作」，不跳中间步。
6. **回连前置**：明确指出哪一步用到了哪个前置节点（引用 ID）。
7. **应用示范**：一个真实场景 + 一个最小可验证示例。
8. **请用户独立推理**：给一个需要自己走完某一步的任务，而不是复述。
9. **依据回答评估**：按 assessment.md 判定是否升级掌握度，并给「下一步」。

## 表征选择（按概念类型）

| 概念类型 | 优先表征 |
|---|---|
| 空间 / 结构关系 | 图、示意图、Mermaid |
| 数学 / 可推导 | 逐步推导，每步注明依据 |
| 编程 / 工具 | 能跑通的最小代码 + 可观察输出 |
| 工程 / 科学现象 | 实验、仿真、数值对照 |
| 抽象关系 | 类比（必须标注是类比）+ 反例 |
| 流程 / 状态变化 | 时序图或状态表 |

类比使用规则：先给类比，再给严格表述，再指出类比在何处失效。不把类比当解释，不把简化模型说成已确立事实。

## 自适应回退决策树

用户表示不懂或答错时：

1. 判断误解类型：术语未懂 / 前置缺失 / 机制跳步 / 类比误导 / 题目表述不清。
2. 术语未懂 → 给该术语的定义 + 一个最小例子，不重讲整节。
3. 前置缺失 → 回退到 `prerequisites[]` 中具体那个节点，只补该节点，再回来。
4. 机制跳步 → 把机制拆成更细的因果步骤，逐步确认。
5. 类比误导 → 撤掉类比，换一种表征重讲。
6. 给一个更简单的例子（变量更少、边界更干净）。
7. 重测，且换一道题，不用原题。

## 硬约束

- **一次只教一个节点、只引入一个新机制**：一课塞入两个新概念即判定不合格，拆成两课。
- 讲解正文 ≤25 行；超过说明该节点还应继续拆分，或改用图表 / 示例替代文字。
- 起始必须确认前置，结尾必须有独立推理任务与完成判据；收到作答并给反馈后才允许进入下一课。
- 禁止用大段文字墙代替交互；不重复同一段解释文字来「再讲一遍」。
- 上述对应 quality-gates.md 的 G4 教学门。
- 不在前置未达标时进入进阶内容。
- 不跳过必要的中间推理（尤其是推导与机制）。
- 区分「已确立事实」与「简化类比 / 工程近似」。
- 不假装用户已经理解：讲解结束不等于掌握，必须有第 8、9 步。
- 不重复用户已掌握的内容；不写鼓励语或空泛评价。
- 讲解篇幅服从当前节点复杂度：一个 L5 原子单元通常 10–25 行足够；超过 40 行说明该节点还应继续拆分。

## 单课结束格式

```
本课节点：<id / name>
掌握度：<之前> → <之后>（依据：<用户作答要点>）
薄弱前置：<节点 ID 或「无」>
下一步：① 继续下一节点 ② 补练 ③ 进入迁移任务 / 反向教学
```
